
# Northstar Support Deflection MVP
## Go-Live Readiness Note

**Team:** [group 21]

**Date:** [12/8/2026 ]



## 1. Purpose

This document summarizes the current readiness of the Northstar Support Deflection MVP.

The MVP is a frontend prototype designed to demonstrate how customers can access information about common support requests without immediately contacting a human support agent.


## 2. What Works

The frontend prototype provides self-service experiences for two support categories:

### Order Status

Customers can:

- Access the order-status section.
- Enter an order number.
- Submit an order-status request.
- View the information provided by the prototype.

### Returns & Refunds

Customers can:

- Access the returns section.
- View return information.
- View refund information.

---

## 3. Frontend Experience

The prototype includes:

- Customer support homepage.
- Navigation between support categories.
- Order-status interface.
- Returns and refunds interface.
- Forms and input fields.
- Buttons and user controls.
- Responsive styling where implemented.

---

## 4. Known Limitations

The current MVP is a frontend prototype and is not production-ready.

Known limitations include:

- No backend service.
- No production database.
- No real-time order information.
- No customer authentication.
- No live inventory integration.
- No real payment or refund processing.
- Some information may be static or demonstration data.
- Additional accessibility testing may be required.
- Production hosting and security configuration are still required.

---

## 5. What Northstar Needs Before Production

A future production version would require:

1. Backend service integration.
2. Connection to Northstar's order-management system.
3. Database integration.
4. Customer authentication.
5. Real-time order information.
6. Secure handling of customer data.
7. Production hosting.
8. Monitoring and error logging.
9. Accessibility testing.
10. User acceptance testing.



## 6. Recommended Next Step

The current frontend prototype should be treated as the foundation for the next development phase.

The next team can connect the existing customer-facing interface to real backend services and production data.
